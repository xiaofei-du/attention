# Attention! marketplace package

Approved direction: name Attention! (identifier attention), one shared notifier for Codex and Claude Code, macOS 14.2+, fresh opening exactly `hey sunshine`. Existing custom openings and preferences remain unchanged. No extra LLM, new speech style, microphone, pause, summary MCP tool, or preview MCP tool.

Two provider packages are generated from the same source and native payload. A repo marketplace contains both provider manifests. Each plugin is self-contained after client caching. `uv` is the explicit prerequisite; pinned requirements provision Python 3.12 and the official MCP SDK. Native universal binaries are supplied, so installation does not compile or need Xcode. Core code and audio assets are copied into an immutable content-addressed runtime outside plugin caches; both providers share Application Support/Attention/state. Installed version-specific launchers keep long-lived turns coherent. Setup never plays audio or asks for recording permission; playback triggers the normal Apple permission flow.

Platform checks precede every Apple-specific import. Unsupported platforms/old macOS return a nonblocking one-time hook warning, then empty successful results; no database, summaries or jobs are created. MCP starts with the same nine tools and returns unsupported-platform status without loading audio modules. Missing uv is a documented prerequisite, not a platform check that can run without a runtime.

Validation uses isolated client config directories, real manifest installation, stdio handshake/tool calls, actual native binary inspection (no speaker output), and fake-platform tests. Existing user hooks, trust, MCP registrations, queue and preferences remain untouched. Public publishing needs a concrete GitHub destination; this turn produces a reviewable local marketplace archive. Installing alongside a legacy hook installation must be detected and suppressed rather than creating a second queue. Migration is documented explicitly before activation; no automatic discovery/copy of personal databases.
