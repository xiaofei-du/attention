# Local notification MCP implementation

> Execute the approved design inline with writing-plans, executing-plans, test-driven-development and verification-before-completion.

**Goal:** Control the shared Codex / Claude Code speech notifier through a small local MCP.

**Architecture:** A stdio SDK server delegates to the existing SQLite Store and local voice/audio helpers. Hooks still bind original-session tokens and receive original-session summaries. Python 3.12 runs the isolated MCP dependencies; the existing Python 3.9 hooks and player remain compatible.

**Spec:** User-approved chat and docs/plan.md MCP decisions, amended September 11: no preview tool; combine opening selection and session-name reporting in set_starter_options.

## Global constraints

- Exactly nine tools: get_status, list_voices, set_voice_preferences, get_starter_sound_options, set_starter_options, set_global_enabled, set_session_enabled, set_summary_preferences, clear_queue.
- No MCP submit_summary, preview_opening, set_opening or separate session-name setter. Existing CLI summary and audition commands remain.
- clear_queue atomically cancels pending jobs across providers; leaves speaking jobs, dedupe receipts, staged summaries and preferences intact. New jobs remain eligible.
- Session controls require the current hook token. Never infer conversation identity from an MCP connection.
- Settings apply only to explicitly requested fields; validate an entire update before writing. Queries never speak or start a worker.
- Summary preferences: target_seconds (10–90, default 30, a soft guide) and custom_instructions (up to 600 UTF-8 bytes, default empty). Preserve same-session generation, conversational context/progress/next, no filler and no duplicate greetings.
- No live queue clearing, preview playback, setting changes, extra model calls or hook-trust changes in validation.
- No unrelated refactors, automatic voice downloads or microphone features. Preserve existing untracked project work; do not commit it wholesale.
